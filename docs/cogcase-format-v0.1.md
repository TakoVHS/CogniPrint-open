# `.cogcase` Evidence Case Format v0.1

Status: **format specification + deterministic manifest primitives implemented; detached digital signing is NOT yet implemented.**

## Purpose

`.cogcase` is a proposed portable evidence-case container for reproducible CogniPrint analysis.

It is designed to answer:

> Which artifact/evidence files were reviewed, which software/reference state was used, and can another reviewer detect later modification?

It is **not** a legal chain-of-custody certification by itself.

## Container layout

A `.cogcase` may be represented as a directory during analysis and later packaged as a ZIP-compatible container:

```text
CASE.json
ORIGINAL/
EVIDENCE/
REFERENCES/
RESULTS/
ENVIRONMENT/
REPORT/
MANIFEST.json
SIGNATURES/
```

### `CASE.json`

Minimal case metadata. Public/synthetic cases should avoid personal identifiers.

Recommended fields:

- schema/version;
- case ID;
- creation time;
- purpose/category;
- source-retention mode;
- evidence-schema version;
- Claim Firewall policy version.

### `ORIGINAL/`

Optional.

For sensitive/zero-retention workflows this directory should be absent from the portable bundle. The case may contain only the source SHA-256 in `CASE.json`/evidence records.

### `EVIDENCE/`

Machine-readable `cogniprint-evidence-v1` records:

- observations;
- inferences;
- attestations;
- unknowns;
- limitations.

### `REFERENCES/`

Reference-registry identifiers/manifests required to reproduce the comparison. Do not silently copy third-party datasets whose licence prohibits redistribution.

### `RESULTS/`

Predictions/metrics/conflict outputs generated by versioned analysis code.

### `ENVIRONMENT/`

Reproducibility metadata, for example:

- code commit;
- environment/container hash;
- configuration hash;
- feature-space version;
- reference-registry version;
- calibration-model version.

### `REPORT/`

Human-readable report generated from machine-readable evidence. The report must not contain stronger claims than the evidence/Claim Firewall permits.

### `MANIFEST.json`

Deterministic file inventory with SHA-256 and size for each payload file.

Implemented primitives: `src/cogniprint/case_manifest.py`.

The manifest itself has a canonical `manifest_sha256`.

### `SIGNATURES/`

Reserved for detached signatures and signer metadata.

**Current status: not implemented.**

A placeholder file or hash must never be represented as a cryptographic signature.

## Manifest integrity

Current implementation can:

- enumerate payload files deterministically;
- hash each file;
- record size;
- hash the canonical manifest body;
- detect changed files;
- detect missing/unexpected payload files;
- reject unsafe manifest paths during verification.

`MANIFEST.json` and `SIGNATURES/` are excluded from the payload file set so a detached signature can later bind the final manifest hash.

## Signing gate

Do not call `.cogcase` "signed" until a reviewed implementation satisfies all of:

- [ ] a modern public-key signature scheme/library is selected and pinned;
- [ ] private keys are never stored in a case/repository;
- [ ] signer public-key/certificate identity and trust model are explicit;
- [ ] signature covers the exact `manifest_sha256`;
- [ ] verification detects manifest modification;
- [ ] key rotation/revocation semantics are documented;
- [ ] test fixtures cover valid, invalid, wrong-key and corrupted cases;
- [ ] the report distinguishes **integrity**, **signature validity**, and **signer trust**.

## Zero-retention mode

For a local/private workflow:

```text
source document
→ local analysis
→ source SHA-256 + bounded evidence
→ source removed/not copied into portable case
```

The portable `.cogcase` may then contain reproducible derived evidence without the raw source.

Zero retention is a workflow property and must be tested; it must not be claimed merely because a field is absent from one JSON object.

## Evidence truth classes

Every case must preserve the difference between:

- `OBSERVED`;
- `INFERRED`;
- `ATTESTED`;
- `UNKNOWN`.

See `docs/evidence-ontology-v1.md`.

## Compatibility contract

Future readers should aim to:

- open older schema versions without silently rewriting meaning;
- reject unsupported future schemas safely;
- preserve unknown fields only when the schema/version policy permits it;
- never upgrade an old evidence class/claim because a newer engine is more capable.

Schema migration must be explicit and versioned.

## Public Case Library

Only synthetic, licensed, public-domain, or explicitly consented examples should enter a public case library.

Each public case should include:

- expected/known provenance where legitimately available;
- CogniPrint evidence output;
- ground truth for the benchmark task;
- success/failure status;
- failure analysis;
- exact software/reference versions.

Marketing-only success cases are not sufficient; failures must be represented.
