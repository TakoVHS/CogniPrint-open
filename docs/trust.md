# CogniPrint Trust & Claim Status

Status date: 2026-07-26

This page is the canonical public trust summary for CogniPrint. It is not a marketing page and it does not expand scientific readiness beyond `descriptive_only`.

## Core rule

CogniPrint separates **capability** from **claim**.

A capability may compute a measurement or comparison. A public claim may be emitted only when the evidence and validation gates required by Claim Firewall are satisfied.

Example:

- capability: compute distance/similarity to a reference distribution;
- prohibited inference by default: “this artifact was generated by family X”.

Similarity is not identity.

## Truth classes

Every evidence record belongs to one of four classes:

- `OBSERVED` — directly measured by the reproducible analysis pipeline;
- `INFERRED` — a bounded statistical inference supported by an explicitly validated inference path;
- `ATTESTED` — supplied by an external provenance/credential source with its own validation state;
- `UNKNOWN` — evidence is insufficient, out of distribution, uncalibrated, conflicting, or the requested claim is unsupported.

CogniPrint does not collapse these classes into one confidence score.

## Scientific readiness

This means CogniPrint currently supports reproducible measurement and evidence structuring. It does not currently have validated source-attribution authority.

## Evidence dimensions are not one confidence number

CogniPrint must keep at least these concepts separate:

- **reference similarity** — how close an artifact is to a stated reference distribution;
- **calibration status/quality** — whether an inference score has demonstrated probability reliability on the relevant validation scope;
- **provenance/attestation strength** — what external credential/log/metadata evidence exists and how it validated.

These must never be magically combined into a headline such as “93% AI”.

## External provenance

C2PA / Content Credentials support is currently an interface contract, not a production runtime capability.

Issue #26 requires known-valid, tampered/invalid, absent and unsupported fixtures plus trust-configuration and privacy review before runtime support may be claimed.

CogniPrint treats external provenance as `ATTESTED` evidence. It does not treat any one external signal as absolute truth and preserves conflicts instead of silently resolving them.

## High-stakes boundary

CogniPrint output must not by itself be used to:

- accuse a person of misconduct;
- automatically punish a student;
- fire or discipline an employee;
- determine legal responsibility;
- identify an operator/commissioner from content alone.

A technical evidence report does not replace domain-specific human review, due process, authenticated external evidence, or legal assessment.

## No-new-feature rule until Challenge 001

Until Evidence Milestone 001 is reached, work that changes project scope is frozen.

Allowed work:

1. correctness/security bug fixes;
2. reproducibility;
3. test/runner infrastructure;
4. preregistration/freeze work;
5. benchmark integrity/sealing;
6. corrections required to keep public claims aligned with evidence.

Deferred work:

- new detector families;
- new dashboards or decorative product layers;
- new regulatory integrations beyond maintaining already-documented mappings;
- additional provenance adapters not required for Challenge 001;
- new headline capabilities.

## Evidence Milestone 001

The milestone is achieved only when all of the following exist together:

- timestamped preregistration;
- actually executed reproducible test suite;
- frozen/sealed blind benchmark;
- frozen prediction artifact and SHA-256;
- post-freeze revealed-label artifact and SHA-256;
- independent evaluator output;
- calibration metrics where calibrated outputs are claimed;
- OOD/UNKNOWN metrics including false-known rate;
- published failure analysis;
- immutable integrity-verifiable evidence bundle;
- external methodological review requested against the actual results.

Reaching this milestone does **not** automatically unlock model-family attribution. A separate Scientific Claim Review must assign each proposed claim one of:

- `ALLOW`;
- `ALLOW_WITH_SCOPE`;
- `REJECT`;
- `REQUIRES_MORE_EVIDENCE`.

The goal of the milestone is not to manufacture a positive result. It is to create a result whose scope cannot be made prettier after the data are known.
